# База данных: SQLite

Отдельный сервер БД не нужен — SQLite это один файл рядом с приложением.

## Расположение файла

Настройка в `src/main/resources/application.yml`:

```yaml
spring:
  datasource:
    url: jdbc:sqlite:cash_store.db?foreign_keys=on&journal_mode=WAL&busy_timeout=5000
```

Файл `cash_store.db` создаётся автоматически при первом запуске в рабочем каталоге приложения
(там же, где лежит EXE/JAR). При первом запуске Flyway применяет миграции из
`src/main/resources/db/migration`.

Параметры в URL — не декорация:

- `foreign_keys=on` — без этого SQLite **не проверяет** внешние ключи вообще (это выключено по
  умолчанию для каждого нового соединения). Без этого параметра ссылочная целостность (например,
  запрет удалить категорию, на которую ссылаются товары) молча не работает.
- `journal_mode=WAL` — Write-Ahead Logging, позволяет читать базу, пока идёт запись (без него
  каждая запись блокирует все чтения).
- `busy_timeout=5000` — если файл на миг занят другим соединением, драйвер подождёт до 5 секунд
  вместо немедленной ошибки `SQLITE_BUSY`.

## Почему не нужен пул соединений

В `application.yml` пул Hikari специально ограничен одним соединением
(`spring.datasource.hikari.maximum-pool-size: 1`). SQLite — однопользовательская база с одним
писателем; больший пул только создаёт риск блокировок между потоками одного и того же приложения,
не давая никакой реальной параллельности.

## Бэкап

Резервная копия — это просто копия файла `cash_store.db` (в режиме WAL заодно скопируйте
`cash_store.db-wal` и `cash_store.db-shm`, если они существуют, либо предварительно выполните
`PRAGMA wal_checkpoint;`, чтобы слить их в основной файл).

## Просмотр базы вручную

Любой SQLite-клиент подходит — например [DB Browser for SQLite](https://sqlitebrowser.org/) или
плагин работы с БД в IntelliJ IDEA (драйвер SQLite нужно подключить отдельно, Postgres-драйвер
для этого файла не подходит).

## Миграции (Flyway)

Миграции лежат в `src/main/resources/db/migration` и применяются при каждом запуске, если появились
новые:

- `V1__init_schema.sql` — вся схема сразу в целевом виде (категории, товары, пользователи, смены,
  кассовые движения, чеки, продажи, быстрые товары, настройки);
- `V2__seed_universal_product.sql` — «универсальный товар» (`universal-product-200001`) для продажи
  позиций без штрихкода по произвольной цене. Пользователя `admin` миграции не создают: его добавляет `SecurityConfig` при старте приложения, если таблица пользователей пуста.

Правила:

- уже применённую миграцию не правят: Flyway сверяет контрольную сумму и откажется запускаться.
  Любое изменение схемы — новый файл `V3__...sql`, `V4__...sql` и так далее;
- `spring.jpa.hibernate.ddl-auto: none` — Hibernate схему не создаёт и не проверяет, источник
  истины только миграции. Проверку «сущности соответствуют схеме» выполняют интеграционные тесты;
- в SQLite один файл и одно пространство имён, поэтому в `@Table` не указывается схема
  (`schema = "main"` из прежней версии на Postgres не используется).

Ограничения, которые обеспечивает сама БД, а не только код:

- не больше одной открытой смены: частичный уникальный индекс `cash_shift_only_one_open` по
  `status` для строк со значением `OPENED`;
- уникальны штрихкод товара, код категории и логин пользователя;
- `foreign_keys=on` защищает ссылки (категория, на которую ссылаются товары, не удаляется;
  при удалении чека его строки продаж удаляются каскадом).

## Денежные суммы

Суммы хранятся в колонках `numeric(15, 2)` и в коде представлены как `BigDecimal`. Перевод из
`double` (суммы в UI) в `BigDecimal` идёт через `UtilNumbers.toMoney`, который округляет до двух
знаков по правилу `HALF_UP`, поэтому сумма вида `0.1 * 7` сохраняется как `0.70`, а не
`0.7000000000000001`. Возвраты хранятся с отрицательными суммами.

## Ошибки ограничений

Нарушение `NOT NULL`, `UNIQUE` или внешнего ключа драйвер SQLite отдаёт так, что Spring
превращает его в `JpaSystemException` (с текстом вида `UNIQUE constraint failed: ...`), а не в
`DataIntegrityViolationException`. Если вы добавите обработку таких ошибок, ловите
`JpaSystemException`.

## Тестовые базы

Интеграционные тесты (`SqliteSchemaIntegrationTest`, `CashFlowSqliteIntegrationTest`) создают
временный файл SQLite в системном каталоге временных файлов, прогоняют на нём реальные миграции и
удаляют его по окончании. Рабочий `cash_store.db` тесты не затрагивают.

## Что не нужно коммитить

`.gitignore` исключает `*.db`, `*.db-wal`, `*.db-shm`, `cash-store.lock` и `logs/`. В базе лежат
продажи, хеши паролей кассиров и пароли доступа к 1С и книге задолженности, поэтому в репозиторий
(и в merge request) её отправлять нельзя. Схему у любого разработчика создаст Flyway при первом
запуске.

## Настройка IntelliJ IDEA

Если проект раньше работал на Postgres, IDEA может показывать ложные ошибки в миграции
(`autoincrement` expected) и предупреждения `Cannot resolve table/column` в сущностях: она
проверяет SQL и сущности по старому Postgres-подключению. На сборку и тесты это не влияет. Как убрать:

1. `Settings → Languages & Frameworks → SQL Dialects` — для проекта или папки
   `src/main/resources/db/migration` выберите диалект **SQLite**;
2. `Settings → Languages & Frameworks → SQL Resolution Scopes` — для проекта выберите
   SQLite-подключение к `cash_store.db` (создаётся запуском приложения);
3. В Database-панели удалите старые Postgres-подключения.

Пустой файл `identifier.sqlite` в корне проекта создаёт само подключение IDEA, не приложение. Если
оно вам не нужно, удалите подключение в Database-панели и затем файл.

## Первый запуск и пользователь по умолчанию

В пустой базе `SecurityConfig` создаёт пользователя `admin` с паролем `admin` (роль `ADMIN`).
Смените пароль сразу после первого входа. Пароли хранятся только в виде BCrypt-хеша.
